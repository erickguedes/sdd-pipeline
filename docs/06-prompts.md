# PROMPT STRUCTURE RULES

Cada prompt deve conter:

1. Objetivo claro
2. Contexto mínimo necessário
3. Stack relevante
4. Arquivos ou áreas afetadas
5. Restrições importantes
6. Resultado esperado
7. Critérios de conclusão
8. Regras arquiteturais relevantes
9. O que NÃO deve ser feito

---

# IMPLEMENTATION RULES

Os prompts devem:
- focar em UMA responsabilidade principal
- evitar múltiplos objetivos conflitantes
- ser incrementalmente seguros
- permitir validação rápida
- minimizar risco de regressão

Sempre prefira:
- pequenas implementações
- entregas verificáveis

- boundaries explícitos

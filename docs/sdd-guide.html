O que é SDD?

Spec-Driven Development é uma abordagem estruturada para desenvolvimento de software assistido por IA, organizado em etapas com handoff explícito.

Diferente do desenvolvimento tradicional ou de prompting avulso, o SDD organiza a criação de software em um fluxo sequencial de especificações: cada etapa produz um artefato que serve como input da próxima, garantindo rastreabilidade, consistência e redução de ambiguidade.

A metodologia foi projetada para funcionar com coding agents (Codex, Cursor, Claude Code, OpenCode, etc.), mas seus princípios são válidos para qualquer contexto de desenvolvimento orientado a especificações.

Detalhamento das Etapas

Cada etapa do pipeline, seu papel, o que consome e o que produz.

Etapa Role Diretiva Gera
/00 — Idea Strategic Product Discovery Partner — valida a ideia, explora o problema, decide GO/NO-GO 00-idea.md generated/idea.md
/01 — Brief Senior Product Manager — consolida discovery em Product Brief com escopo MVP claro 01-brief.md generated/brief.md
/02 — PRD Senior Product Requirements Engineer — traduz briefing em requisitos, épicos e stories 02-prd.md generated/prd.md
/03 — Architecture Senior Software Architect — define stack, padrões, estrutura do sistema e convenções 03-architecture.md generated/architecture.md
/04 — UX/UI Senior UX Strategist — especifica telas, componentes, interações e estados 04-ux-ui.md generated/ux-ui.md
/05 — Tasks Senior Tech Lead — organiza milestones, dependências e task breakdown incremental 05-tasks.md generated/tasks.md
/06 — Prompts AI Implementation Orchestrator — transforma tasks em prompts executáveis para coding agents 06-prompts.md generated/prompts.md

Como Usar

O fluxo de trabalho é simples: execute cada etapa em sequência, alimentando a próxima com o artefato gerado.

1

Execute a diretiva de cada etapa

Abra o arquivo docs/00-idea.md no seu coding agent e siga as instruções. O agente assumirá o role descrito e conduzirá a conversa.

2

Salve o artefato gerado

Ao final da etapa, o agente gera o output em docs/generated/. Esse arquivo servirá como contexto para a próxima etapa.

3

Avance para a próxima etapa

Com o artefato da etapa anterior como input, execute a diretiva seguinte. O handoff está documentado na seção HANDOFF OUTPUT de cada arquivo.

4

Ao final, execute os prompts

A etapa 06-prompts.md produz prompts prontos para implementação. Basta copiá-los para seu coding agent favorito e executar.

Na Prática

Exemplo real de uso do pipeline SDD com OpenCode — do git clone aos prompts de implementação.

1

Clone o repositório

git clone https://github.com/seu-user/sdd-pipeline.git
cd sdd-pipeline

2

Inicie o OpenCode no diretório

npx opencode — ou use opencode diretamente se instalado globalmente. Certifique-se de que o OpenCode tenha permissão de leitura/escrita nos arquivos.

3

Execute a Etapa /00 — Idea

Dentro do OpenCode, peça para abrir e seguir a diretiva: docs/00-idea.md. O agente assumirá o papel de Strategic Product Discovery Partner e conduzirá a conversa para validar sua ideia. Ao final, salve o artefato gerado em docs/generated/idea.md.

4

Avance para /01 — Brief

Com o artefato gerado como contexto, execute docs/01-brief.md. O agente agora atua como Senior Product Manager, consolidando o discovery em um Product Brief. Output: docs/generated/brief.md.

5

Continue sequencialmente até /06

Siga o mesmo fluxo para as etapas 02 a 06. Cada diretiva consome o artefato da etapa anterior e gera o próximo. Não pule etapas — o handoff é o que garante a consistência entre sessões e agentes.

6

Execute os prompts finais

A etapa docs/06-prompts.md produz docs/generated/prompts.md com prompts prontos. Copie cada prompt no OpenCode (ou outro coding agent) e implemente incrementalmente. Cada prompt é autocontido e tem boundaries claros — não precisa de contexto anterior.

Dica: Você não precisa usar o OpenCode — o pipeline funciona com Codex, Cursor, Windsurf, Claude Code, Gemini CLI e qualquer coding agent compatível com markdown. O importante é seguir a ordem e respeitar o handoff.
